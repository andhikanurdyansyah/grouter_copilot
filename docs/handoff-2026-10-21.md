## Masalah yang diselesaikan

CI merah sejak **2026-10-18** — delapan push berturut-turut. Karena gate
`Source scan` berada di langkah ke-6, langkah sesudahnya **tidak pernah
berjalan sekali pun**: server suite, typecheck, lint, dan isolated E2E nol
cakupan CI selama tiga hari. Itu risiko yang lebih besar daripada bug-nya.

### 1. Source scan memindai file test (`34cc21b`)

`scripts/source-scan.mjs` mengecualikan **direktori** (`test/`, `examples/`),
padahal repo ini menaruh mounted behavior test **di dalam** root yang dipindai
(`frontend/src/features/**/*.behavior.test.tsx`). Test seperti itu memang
mem-mock API, jadi aturan `mock-data-in-production` menyala pada tiga baris
setup test yang sah — dan gagal, sementara kode produksi bersih.

Perbaikan: lewati file test/spec **berdasarkan nama** di mana pun di bawah root
yang dipindai; modul produksi di direktori yang sama tetap dipindai. Regresi
menguji kedua sisi.

### 2. `npm install -g npm@12` merusak runner (`205dacd`)

Dry-run pertama `publish.yml` gagal **sebelum satu gate berjalan**:

```
npm error code MODULE_NOT_FOUND
npm error Cannot find module 'promise-retry'
... /opt/hostedtoolcache/node/22.22.2/x64/lib/node_modules/npm/...
```

Memasang npm global menimpa tree npm toolcache **saat npm lama masih
mengeksekusi dirinya sendiri**. Pin `node-version: '22.22.2'` perlu tapi tidak
cukup — kegagalannya hanya berpindah. Sekarang npm 12 dipasang ke
`$RUNNER_TEMP/npm12` dan bin-nya di-`prepend` ke `PATH`, lalu versinya
**diverifikasi** (`12.*`), supaya fallback diam-diam ke npm toolcache tidak
lolos sebagai sukses.

### 3. Root suite butuh `server/node_modules` (`b49a7f1`)

Komentar langkah menyebut root suite "zero-dependency". Itu sudah tidak benar:
empat test isolasi E2E menyusun schema better-auth di child process dengan
`cwd: server/`, jadi me-resolve `better-auth` dari `server/node_modules`. Di
host dev dependensi itu ada; di runner bersih tidak — 4 test gagal
`Cannot find package 'better-auth'`, dan gate publish tidak akan pernah lulus.

### 4. Guard fail-closed di-shadow oleh import statis (`9fdc254`)

`playwright.config.mjs` meng-import playwright di baris atas, **sebelum** guard
`E2E_ISOLATED`/loopback. Resolusi modul terjadi lebih dulu, jadi tanpa
frontend deps config gagal dengan `MODULE_NOT_FOUND`, bukan dengan penolakan
yang dimaksud. Dua akibat: guard non-loopback tidak pernah dieksekusi, dan
pemanggil tidak bisa membedakan "run produksi diblokir" dari "checkout rusak".

Sekarang guard jalan dulu, playwright dimuat lewat `await import()` sesudahnya.
Terverifikasi tiga jalur: tanpa `E2E_ISOLATED` → ditolak; origin publik →
ditolak; loopback → config memuat kedua project.

### 5. Server suite mustahil lulus di checkout bersih (`cd2d0dd`)

Setelah source-scan diperbaiki, server suite **pertama kali** benar-benar
berjalan di CI dan **28 test gagal**. Akar masalahnya: tujuh file test menyalin
`server/data/auth.sqlite` (artefak PRODUKSI yang gitignored) untuk mendapatkan
schema Better Auth, karena library itu tidak punya auto-migration dan melempar
`SchemaMismatchError` pada file tanpa schema. Di host dev file itu ada; di
checkout bersih tidak → `ENOENT` saat import.

- `src/auth.js` sekarang membuat schema lewat migrasi **hanya bila file yang
  di-resolve memang belum punya schema** — diputuskan dengan memeriksa file
  (`sqlite_master`), bukan menebak jalur kode, karena test yang memberi
  `AUTH_DB_FILE` kosong sendiri pun kena dinding yang sama. Produksi dan DB yang
  sudah punya schema tidak disentuh (nol tulisan saat boot).
- Tujuh situs copy memakai `server/test/helpers/auth-db-fixture.mjs`: salin bila
  schema prod tersedia, biarkan absen bila tidak.
- `auth-db-isolation.test.js` memakai sentinel saat data prod tidak ada, supaya
  invariannya tetap terbukti di checkout bersih.

### 6. Lint error di test mounted (`36cd43c`)

### 7. Chromium di-hardcode ke host ini (`b01caaa`)

### 8. Tombol submit sign-up bergeser saat diklik (`72dc56e`)

Satu-satunya kegagalan sisa di CI, khusus mobile:

```
[mobile] locator.click: Timeout 15000ms exceeded
  <div class="absolute inset-0 z-0"> intercepts pointer events
  <input aria-label="Confirm Password"> intercepts pointer events
```

Diukur di 390px: posisi-x tombol `Finish sign-up` bergerak **341 → 307,5 → 301**
dalam ~300ms. Dua sebab:

1. Form memakai `w-[300px]` di dalam fieldset `w-[280px] p-4` (konten 248px) →
   overflow, tombol keluar dari kotak fieldset.
2. Tombol berada di container yang dianimasikan `w-0 → w-10` selama 300ms →
   hit target benar-benar bergeser saat klik dikirim.

Perbaikan: fieldset `min-w-0 max-w-full` dengan anak `w-full max-w-[300px]`;
slot tombol tetap `w-10` dan hanya opacity yang dianimasikan
(`pointer-events-none` saat tersembunyi). Delapan sampel 100ms: bundle lama
tidak pernah stabil, bundle baru konstan `x=275`; klik non-forced ~99ms.

### 11. Klik submit E2E memakai bounding box yang sudah usang (`cc0492e`)

Setelah 0.1.1 terbit, CI `8862a20` merah di langkah Isolated E2E:
`1 failed, 21 passed`, khusus `[desktop]`, dengan
`<div class="glass-input"> intercepts pointer events`.

Yang membuat ini mahal untuk didiagnosis: spec yang sama **lulus** kalau
dijalankan sendiri. Tiga run `E2E_GREP` berturut-turut hijau, dua run suite
penuh berturut-turut gagal. Jadi ini bergantung beban, bukan regresi produk —
dan memfilter ke satu spec justru menyembunyikannya.

Dua sebab nyata, keduanya di helper:

1. Klik dikirim tepat setelah `fill()` pada field konfirmasi. Fill itu memulai
   dua animasi (label "Confirm Password" 0.3s dan BlurFade 0.4s). Playwright
   menghitung titik klik dari bounding box yang dibaca sebelum elemen diam,
   sehingga titiknya jatuh di wrapper input di belakangnya.
2. Menunggu `state: 'stable'` tidak cukup: easing cubic-bezier bisa memberi dua
   frame berurutan yang hampir identik padahal masih bergerak sub-piksel, jadi
   percobaan ulang membaca kotak usang yang sama.

Perbaikan: `scrollIntoViewIfNeeded()` dulu (`elementFromPoint` mengembalikan
null untuk koordinat di luar viewport — persis kasus viewport 390x844 di dalam
project desktop), lalu tunggu kondisi yang benar-benar dibutuhkan klik:
hit-test di titik tengah tombol harus mengembalikan tombol itu. Dua run suite
penuh berturut-turut: **22/22**, prod byte-identik.

  `probe-…` ke `server/data/auth.sqlite` (hash bergeser `dd69063…` →

  benar dibandingkan adalah **jumlah baris dan integritas**, bukan hash, setelah
  ada tulisan yang disengaja. `store.json` tidak tersentuh (`764b368b…`).
  Aturan: probe UI yang melakukan sign-up selalu ke instance terisolasi
  (`DATA_FILE=$TMP PORT=4690` atau `npm run e2e`), atau ke build lokal via
  `vite preview`.
- `git stash push -- <file>` **tidak membuat stash baru** kalau file itu sudah
  identik dengan HEAD; perintahnya no-op dan `git stash pop` berikutnya
  memunculkan stash **lama** (`my-moda-rebuild-backup-2026-10-11`). Ini terjadi
  di sesi ini dan sempat mengotori tree dengan 21 konflik.
  Pemulihan aman: `git reset --hard HEAD` (stash tidak hilang), lalu hapus
  hanya file untracked yang **terbukti** berasal dari `stash@{0}^3`
  (`comm -23` terhadap `git ls-tree -r --name-only stash@{0}^3`). Stash lama
  tetap utuh dan bisa di-pop kapan pun.
- Untuk uji RED, lebih aman **salin file ke scratch, ubah, jalankan, salin
  balik** daripada stash. Itulah yang dipakai untuk membuktikan test guard
  urutan import.
